# E0–E3 统一复评交接

## 复评口径

本目录使用 A 分支 `feature/focal-loss` 的统一 `evaluate.py`，在同一份 PA-100K 验证集上复评官方 E0、E3 和 E3b。二值属性使用 `logits > 0`，年龄与方向组使用 `argmax` 后转 one-hot；宏指标对 26 个属性等权平均，实例指标先逐图计算再取平均。

- 验证样本数：10,000
- `val.csv` SHA-256：`c99e7cc03fab148b932d4c5e66292c5e3008b648a714a451c98ecf4d4595a88c`
- 本机环境：Python 3.9.21、PyTorch 2.5.1、torchvision 0.20.1、Pillow 11.1.0、CUDA、RTX 4060 Laptop GPU
- batch size / workers：64 / 4

## 为什么尚不能发布最终五模型总表

A 的服务器结果使用 Python 3.10.22、PyTorch 2.1.2+cu118、torchvision 0.16.2+cu118、Pillow 10.4.0 和 RTX 4090。即使使用相同 E0 权重、相同 `val.csv` 和同一评估脚本，服务器 E0 与本机 E0 仍有少量阈值附近样本翻转：

| E0 环境 | 九组 AttrAcc | 宏 mA | 宏 F1 | 实例 F1 |
| --- | ---: | ---: | ---: | ---: |
| A 服务器 | 92.3576% | 76.8736% | 63.1667% | 83.6997% |
| 本机统一复评 | 92.3602% | 76.9107% | 63.2039% | 83.7057% |

差异虽小，但最终表不应混用两种推理环境。A 分支目前已经提交 E1a/E1b 的配置、评估 JSON 和权重哈希，但没有公开两份 `best.pt`。完成最终五模型统一复评只缺：

1. `E1a_pos_weight_best.pt`，SHA-256 应为 `19affea68f877b29a5ebccf810e145012548a6dfccca98020ab0dea91e67565b`；
2. `E1b_focal_best.pt`，SHA-256 应为 `d2fa32ee72fd83164422bdeece6a0096de12b4dfd951405cab87f152fc7ec7e5`。

取得这两份权重后，应在本机用本目录相同环境一次性复评 E0、E1a、E1b、E3、E3b，再生成最终横向表，不需要重新训练。
